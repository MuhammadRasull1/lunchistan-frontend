## Что сделано (11–12.09)

**Меню больше не в коде.** Было захардкожено в `mockMenu.ts` — теперь приходит с
бэкенда, редактируется владельцем через экран «Меню» (добавить/изменить/скрыть),
без передеплоя. Таблица `menu_sets` получила описание, фото, КБЖУ, состав, is_active.

**Оплата картой — простой вариант** (решение дяди, не эквайринг): таблица
`settings`, экран «Настройки» у владельца, в корзине показывается номер карты и
держатель. Пока номера нет — честное «уточняется».

**Тёзки в «Командах» (12.09).** Два бага, оба чинились вместе:
- Регистрация не проверяла имя внутри команды — второй «Иван» получал учётку,
  в которую невозможно войти. Теперь 409 с понятным текстом.
- Вход по имени при нескольких тёзках отдавал «Неверное имя или пароль», хотя
  пароль верный. Поля для кода команды в форме входа не было — человек
  блокировался навсегда. Теперь тёзки различаются по паролю (обычно хватает),
  а код команды запрашивается только когда различить нечем.

**Размер команды** — необязательное поле в форме «Создать команду» (бэкенд и
`ManagerView` умели это и раньше).

**Чистка** — удалено 33 неиспользуемых ключа перевода от старого `TeamsAuth`.
Ключи `status_*` оставлены: собираются динамически в `orderStatus.ts`.

Проверено: смоук 31/31, tsc/eslint/build чисто.

## Ожидания от пользователя
- [ ] Проверить онбординг глазами в браузере (`npm run dev` + бэкенд на :5000,
      `VITE_API_BASE_URL=http://localhost:5000` в `.env.local`). HTTP-слой всех
      трёх путей (вход / создать / по коду) проверен живьём, внешний вид — нет.
- [ ] Взять у дяди номер карты → Настройки в приложении, код трогать не нужно.
- [ ] Взять с ноутбука брата актуальное меню (в базе пока старые 56 блюд).
- [ ] Взять структуру учёта (расходы/доходы/зарплаты) — таблиц в БД нет вообще,
      это «сделать с нуля», а не «доделать».

## Открытые вопросы
- Онбординг: нужен ли шаг подтверждения, что человек попал в правильную команду.
- Уникальность имени теперь на уровне API, но не на уровне БД — если когда-нибудь
  появится второй способ создавать пользователей, ограничение надо продублировать
  в `schema.sql`.
