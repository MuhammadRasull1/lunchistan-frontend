## 1. Бизнес-модель

Lunchistan — сервис корпоративной подписки на комплексные обеды.  
Компании подписываются на **ежемесячную доставку обедов** для своих сотрудников.

## 3. Ценообразование

### 3.1. Базовая цена

| Параметр           | Значение                         |
| ------------------ | -------------------------------- |
| **Цена одного сета** | **55 000 сум** (фиксировано)   |
| Константа          | `export const SET_PRICE = 55000` |

### 3.2. Формула стоимости (v2.0)

```
selectedDates = ключи cartState (только выбранные дни)
totalPortionsFromActive = Σ(portions каждого выбранного дня)
totalItems = totalPortionsFromActive × employeeCount
totalMonthlyPrice = totalPortionsFromActive × employeeCount × SET_PRICE
```

Где:
- `selectedDates.length` — количество **выбранных дат календаря** (единственный источник, старый `workDaysCount` удалён);
- `employeeCount` — количество сотрудников (множитель);
- `portions` — количество порций на одного сотрудника для конкретной даты (по умолчанию 1);
- наличие даты в `cartState` = день выбран.

### 3.3. Пример расчёта

```
Сотрудников: 10
Выбранных дат: 20 (по 1 порции на день)
Итого: 20 × 10 × 55 000 = 11 000 000 сум
```

## 4. Рабочие дни через календарь (v2.0)

- Пользователь выбирает **реальные даты доставки** в календаре рабочих дней ([[COMPONENTS#35-calendartsx-календарь-рабочих-дней-v20]]).
- Период: **текущий месяц** (по умолчанию) + переход на **следующий месяц**; граница «недопустимого периода» = текущий → следующий.
- **Начало подписки** = 1-е число видимого месяца (день №1 паттерна пресетов).
- Допустимые даты — **Пн–Пт**; суббота и воскресенье не выбираются.
- Количество дней определяется **исключительно** `selectedDates.length` — абстрактный счётчик `workDaysCount` удалён ([[STATE_MANAGEMENT#3-вычисляемые-значения-derived-state]]).
- Дата → сет меню: **стабильно по числу месяца** (`MONTHLY_SETS[день-1]`), поэтому удаление дня не меняет меню остальных дат.

### 4.1. Пресеты графика (v2.0)

| Пресет  | Паттерн (от 1-го числа видимого месяца, по последовательности Пн-Пт) |
| ------- | ------------------------------------------------------------ |
| `2/2`   | рабочий × 2 → выходной × 2 (цикл 4)                          |
| `5/2`   | рабочий × 5 → выходной × 2 (цикл 7)                          |
| `6/1`   | рабочий × 6 → выходной × 1 (цикл 7)                          |
| Весь месяц | все допустимые даты (Пн-Пт) текущего периода                |

Применение пресета: очистить текущий список выбранных дат → построить новый график → обновить state → пересчитать цену. Реализация: `buildPresetDates()` в `src/lib/calendar.ts`.

## 5. Логика employeeCount как множителя

- `employeeCount` (по умолчанию `1`) — количество сотрудников компании.
- Этот параметр **умножает** стоимость:
  - `totalItems = totalPortionsFromActive × employeeCount`
  - `totalMonthlyPrice = totalItems × SET_PRICE`
- Минимальное значение: `1`
- Начальное значение: `1` (сбрасывается при `handleNewOrder()`)

## 7. Включение/выключение дней (v2.0)

- Каждая дата календаря включается/выключается кликом: **не выбран → выбран → не выбран**.
- При выключении дня его настройки (салат, напиток, порции) **удаляются из state**, и день не попадает в `days[]` заказа.
- Массовые операции в пределах видимого месяца:
  - **«Выбрать все N дней»** — `handleSelectAllInMonth(monthKey)` (все Пн-Пт месяца)
  - **«Сбросить все»** — `handleDeselectAllInMonth(monthKey)` (только видимый месяц)

## 8. Исключение ингредиентов (v1.3)

- В модалке сета ([[COMPONENTS#5-setdetailmodaltsx]]) второстепенные компоненты — **Салат, Лепёшка, Напиток** — кликабельны.
- При клике ингредиент **исключается**: серый чип с зачёркиванием переносится в блок **«Без этих ингредиентов»**; повторный клик возвращает его обратно.
- 🛡️ **Защита от абуза:** основное блюдо (main dish) **заблокировано** от исключения (`disabled` + `Lock` + подсказка `mainDishLocked`). Убрать главное блюдо НЕЛЬЗЯ.
- Исключения хранятся в `cartState[id].excludedIngredients: string[]` ([[STATE_MANAGEMENT#2-2-cartstate—детальная-структура]]) и **сохраняются в итоговом объекте заказа** (`lines[].excludedIngredients`) → [[CHECKOUT_FLOW#5-2-обработка-заказа]].
- В [[COMPONENTS#6-carttsx—экран-корзиныоформления]] для таких дней отображается строка «без: Салат, Лепёшка».
- **Цена не меняется** при исключении ингредиентов (фиксированный сет 55 000 сум).

## 9. Количество порций (Portions)

- Для каждого активного дня можно указать количество порций на одного сотрудника.
- Минимум: `1`
- По умолчанию: `1`
- UI: счётчик `--` / `значение` / `++`.
- Кнопка `--` отключается при `portions <= 1`.

## 10. Форма оформления заказа (Cart)

### 10.1. Текущее состояние

⚠️ **Важно:** На данный момент форма заказа **минимальна**.  
В `Cart.tsx` отображаются:

- Список выбранных сетов с детализацией (день, напиток, порции, цена)
- Выбор **способа оплаты** (см. п. 9.2)
- Итоговая сумма

**Поля, которые НЕ реализованы, но подразумеваются бизнес-логикой:**

| Поле                     | Описание                              | Статус       |
| ------------------------ | ------------------------------------- | ------------ |
| Имя / ФИО контактного лица | Кто оформляет заказ                  | ❌ Не реализовано |
| Телефон                  | Контактный номер телефона             | ❌ Не реализовано |
| Адрес доставки           | Куда доставлять обеды                 | ❌ Не реализовано |
| Окно времени доставки    | Желаемое время доставки               | ❌ Не реализовано |
| ИНН / Название компании  | Для юрлиц (при оплате перечислением)  | ❌ Не реализовано |
| Комментарий              | Дополнительные пожелания              | ❌ Не реализовано |

### 10.2. Способы оплаты (PaymentMethod)

| Метод          | Значение      | Описание (RU)              | Эмодзи |
| -------------- | ------------- | -------------------------- | ------ |
| Перечислением  | `'corporate'` | Для юридических лиц        | 🏢     |
| Перевод на карту | `'card'`    | P2P перевод                | 💳     |
| Наличными      | `'cash'`      | Наличными курьеру          | 💵     |

🆆 **Локализация:** подписи кнопок оплаты переведены на узбекский (Ko'chirma orqali, Kartaga o'tkazma, Naqd pul).

По умолчанию: `'corporate'`.

### 10.3. Процесс оформления

1. Пользователь нажимает «Оформить предзаказ» / «Buyurtma berish» в Catalog
2. Открывается экран Cart с детализацией
3. Выбор способа оплаты
4. Нажатие «Оплатить N сум» / «N so'm to'lash»
5. `handlePlaceOrder(method)` → `console.log` + локализованный `alert` → `setScreen('success')`
6. Экран Success с анимацией и номером заказа
7. Кнопка «Сделать новый заказ» / «Yangi buyurtma» → полный сброс
