## 1. Бизнес-модель

Lunchistan — сервис корпоративной подписки на комплексные обеды.  
Компании подписываются на **ежемесячную доставку обедов** для своих сотрудников.

## 3. Ценообразование

### 3.1. Базовая цена

| Параметр           | Значение                         |
| ------------------ | -------------------------------- |
| **Цена одного сета** | **55 000 сум** (фиксировано)   |
| Константа          | `export const SET_PRICE = 55000` |

### 3.2. Формула стоимости (v2.0)

```
selectedDates = ключи cartState (только выбранные дни)
totalPortionsFromActive = Σ(portions каждого выбранного дня)
totalItems = totalPortionsFromActive × employeeCount
totalMonthlyPrice = totalPortionsFromActive × employeeCount × SET_PRICE
```

Где:
- `selectedDates.length` — количество **выбранных дат календаря** (единственный источник, старый `workDaysCount` удалён);
- `employeeCount` — количество сотрудников (множитель);
- `portions` — количество порций на одного сотрудника для конкретной даты (по умолчанию 1);
- наличие даты в `cartState` = день выбран.

### 3.3. Пример расчёта

```
Сотрудников: 10
Выбранных дат: 20 (по 1 порции на день)
Итого: 20 × 10 × 55 000 = 11 000 000 сум
```

## 4. Рабочие дни через календарь (v2.1)

- Пользователь выбирает **реальные даты доставки** в календарной модалке ([[COMPONENTS#35-calendarmodaltsx—модалка-выбора-дат-v21]]), открываемой кнопками «Выбрать дни» / «Сбросить все» на главном экране.
- Период: **текущий месяц** (по умолчанию) + переход на **следующий месяц**; граница «недопустимого периода» = текущий → следующий.
- **Начало подписки** = 1-е число видимого месяца (день №1 паттерна пресетов).
- 🆆 **v2.1:** выбираются **все календарные даты**, включая субботу и воскресенье (ранее — только Пн–Пт).
- Количество дней определяется **исключительно** длиной подтверждённого выбора (раньше `selectedDates.length`, теперь массив `dates`, применённый через `handleApplySelectedDates`) — абстрактный счётчик `workDaysCount` удалён ([[STATE_MANAGEMENT#3-вычисляемые-значения-derived-state]]).
- Дата → сет меню: **глобальная порядковая привязка** (`getSetForDate`: `MONTHLY_SETS[(ordinal-1) % 56]`, ordinal = счёт дней от 1-го числа текущего месяца, даты следующего месяца продолжают счёт; модуль 56 делает достижимым каждый сет). Детерминировано — удаление дня не меняет меню остальных дат.
- 🆆 **Правила дат (v2.7):** прошлые даты недоступны для выбора (залочены в календаре + отфильтровываются в `App.tsx`); «сегодня» кликабельно только до временной резки `TODAY_ORDER_CUTOFF_HOUR = 10` — единый предикат `canSelectDate(date)` во всех путях выбора (клик, пресеты, «Выбрать все»).

### 4.1. Пресеты графика (v2.4)

Рабочая неделя в UZ-контексте — **6 дней: Пн–Сб**, выходной — вс.

| Пресет  | Семантика (видимый месяц, применяется к календарным дням) |
| ------- | ---------------------------------------------------------- |
| `2/2`   | цикл «рабочий × 2 → выходной × 2» по **всем** дням месяца (якорь: 1-е число = день №1); сб/вс участвуют в цикле наравне |
| `5/2`   | рабочие **пн–пт**, выходные сб–вс (по дню недели, якорь не важен) |
| `6/1`   | рабочие **пн–сб**, выходной **вс** (по дню недели) |
| Весь месяц | все календарные дни видимого месяца (включая сб/вс) |
| 🆆 Вся неделя | toggle: **все дни Пн..Вс** конкретной строки недели (повторное нажатие снимает) |

**Toggle-поведение (v2.2):** все глобальные пресеты (`2/2`, `5/2`, `6/1`, `full`) — toggle на **черновике модалки**:
- первое нажатие добавляет даты пресета в видимый месяц (другие месяцы не затрагиваются);
- повторное — снимает **ровно пресетные даты**; вручную добавленные/снятые дни сохраняются;
- активный пресет подсвечивается (`.calendar__preset--active`), когда выбор видимого месяца в точности равен его результату.

Применение подтверждается только кнопкой «Подтвердить» → `handleApplySelectedDates()` → пересчёт цены. Реализация: `buildPresetDates()`, `buildMonthWeeks()`, `workWeekDatesOf()` в `src/lib/calendar.ts`, `togglePreset()` / `isPresetActive()` в [[COMPONENTS#35-calendarmodaltsx—модалка-выбора-дат-v22]].

## 5. Логика employeeCount как множителя

- `employeeCount` (по умолчанию `1`) — количество сотрудников компании.
- Этот параметр **умножает** стоимость:
  - `totalItems = totalPortionsFromActive × employeeCount`
  - `totalMonthlyPrice = totalItems × SET_PRICE`
- Минимальное значение: `1`
- Начальное значение: `1` (сбрасывается при `handleNewOrder()`)

## 7. Включение/выключение дней (v2.1)

- Каждая дата в модалке включается/выключается кликом: **не выбран → выбран → не выбран** (операции на черновике, [[STATE_MANAGEMENT#4-обработчики-событий]]).
- При выключении дня (при подтверждении) его настройки (салат, напиток, порции) **удаляются из state**, и день не попадает в `days[]` заказа.
- Массовые операции в пределах видимого месяца (на черновике модалки):
  - **«Выбрать все N дней»** — все даты видимого месяца (включая Сб/Вс)
  - **«Сбросить все»** — снять выбор только в видимом месяце
- Результат применяется к основному state заказа **только после «Подтвердить»** через `handleApplySelectedDates()`.

## 8. Исключение ингредиентов (v1.3)

- В модалке сета ([[COMPONENTS#5-setdetailmodaltsx]]) второстепенные компоненты — **Салат, Лепёшка, Напиток** — кликабельны.
- При клике ингредиент **исключается**: серый чип с зачёркиванием переносится в блок **«Без этих ингредиентов»**; повторный клик возвращает его обратно.
- 🛡️ **Защита от абуза:** основное блюдо (main dish) **заблокировано** от исключения (`disabled` + `Lock` + подсказка `mainDishLocked`). Убрать главное блюдо НЕЛЬЗЯ.
- Исключения хранятся в `cartState[id].excludedIngredients: string[]` ([[STATE_MANAGEMENT#2-2-cartstate—детальная-структура]]) и **сохраняются в итоговом объекте заказа** (`lines[].excludedIngredients`) → [[CHECKOUT_FLOW#5-2-обработка-заказа]].
- В [[COMPONENTS#6-carttsx—экран-корзиныоформления]] для таких дней отображается строка «без: Салат, Лепёшка».
- **Цена не меняется** при исключении ингредиентов (фиксированный сет 55 000 сум).

## 15. 🆆 Раздел «Команды» (v3.1)

Модель после решения владельца (2026-09-05) — замена auth-shell:

- **Главный экран — Каталог** (без входа). Рядом вкладка **«Команды»**.
- **Создать команду**: менеджер вводит имя + **кол-во людей** (поле `size`, бекенд `companies.size`) + свои данные (имя/телефон/пароль) → получает **код 6 символов**.
- **Сотрудник** присоединяется по коду (имя/телефон/пароль) и **сам** выбирает: какие дни доставки (токен = день) и какое **блюдо из 56 сетов** на каждый день. Не выбрал → сет-дефолт (порядковая ротация `(ordinal-1)%56`, совпадает с каталогом).
- **Менеджер**: карточка команды (код для копирования, занято `людей / size`), сводка дня (блюдо × N, дефолты отдельно, итог × 55 000), **подтверждение** дня → Telegram-чек. Повторный confirm → 409.
- **Дедлайн**: день редактируется до 10:00 (Asia/Tashkent) накануне; «сегодня» после 10:00 и прошлые дни — locked.
