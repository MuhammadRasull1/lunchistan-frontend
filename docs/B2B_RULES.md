## 1. Бизнес-модель

Lunchistan — сервис корпоративной подписки на комплексные обеды.  
Компании подписываются на **ежемесячную доставку обедов** для своих сотрудников.

---

## 2. Меню — 24 рабочих дня

- **24 обеда** на месяц (Пн–Пт × 4–5 недель).
- Каждый день — **уникальный сет** (основное блюдо + салат + лепёшка + напиток).
- Данные хранятся в `src/data/mockMenu.ts` как массив `MONTHLY_SETS`.
- Пример основного блюда: «Гушт сай с лепёшкой», «Курица с грибами и рисом» и т.д.
- Все 24 дня — рабочие (выходные не входят в модель подписки).

### 2.1. Категории сетов (v1.4)

Каждый сет имеет поле `category` (тип `SetCategory`):

| Категория    | Значение     | Состав                                                            |
| ------------ | ------------ | ----------------------------------------------------------------- |
| **Мясо**     | `'meat'`     | Говядина/баранина (гушт сай, гуляш, плов, бефстроганов, манты…) — 14 сетов |
| **Курица**   | `'chicken'`  | Блюда из курицы (курица с грибами, терияки, наггетсы, шашлык…) — 6 сетов |
| **Птица**    | `'poultry'`  | Блюда из птицы (индейка запечённая, котлеты из индейки) — 2 сета  |
| **Рыба**     | `'fish'`     | Блюда из рыбы (рыба запечённая с рисом, рыбные котлеты) — 2 сета  |

> ✅ **v1.4:** рыбные сеты вынесены из «Птицы» в собственную категорию **«Рыба»** (`'fish'`). Категории «Курица» и «Птица» содержат **исключительно блюда из птицы**.

UI: табы «Все / Мясо / Курица / Птица / Рыба» в [[COMPONENTS#3-4-табы-категорий-v13]].

### 2.2. Формат описания сета

```
Обед День X (ДеньНедели) — Основное блюдо + Салат + Лепёшка + Напиток
```

Пример:  
`Обед День 1 (Пн) — Гушт сай с лепёшкой + Салат + Лепёшка + Напиток`

### 2.3. Пищевая ценность (КБЖУ) — стандарт 400 г (v1.3)

**Стандарт:** общий вес комплексного сета ≈ **400 г**  
(основное блюдо ~280 г + салат ~60 г + лепёшка ~40 г + напиток ~20–50 г).

Реалистичные диапазоны калорийности:

| Тип сета                                   | Калорийность      | Примеры (ккал)                   |
| ------------------------------------------ | ----------------- | -------------------------------- |
| Сытные сеты с пловом/макаронами            | **650–850 ккал**  | Плов свадебный 780, плов домашний 760 |
| Сеты с мясом (гуляш, бефстроганов, бифштекс)| **600–720 ккал**  | Котлеты по-киевски 700, парамач 720 |
| Лёгкие сеты с птицей/рыбой/салатом         | **450–600 ккал**  | Курица с грибами 520, рыба 480, индейка 500 |

Данные хранятся в массиве `KBJU_DATA` в [[mockMenu.ts]] и отображаются в блоке «Пищевая ценность» модалки сета → [[COMPONENTS#5-setdetailmodaltsx]].

## 3. Ценообразование

### 3.1. Базовая цена

| Параметр           | Значение                         |
| ------------------ | -------------------------------- |
| **Цена одного сета** | **55 000 сум** (фиксировано)   |
| Константа          | `export const SET_PRICE = 55000` |

### 3.2. Формула стоимости

```
totalPortionsFromActive = Σ(portions каждого активного дня)
totalItems = totalPortionsFromActive × employeeCount
totalMonthlyPrice = totalPortionsFromActive × employeeCount × SET_PRICE
```

Где:
- `employeeCount` — количество сотрудников (множитель)
- `portions` — количество порций на одного сотрудника для конкретного дня (по умолчанию 1)
- `active` — включён ли день в подписку

### 3.3. Пример расчёта

```
Сотрудников: 10
Активных дней: 20 (по 1 порции на день)
Итого: 20 × 10 × 55 000 = 11 000 000 сум
```

## 4. Гибкое количество рабочих дней

- Пользователь может выбрать **от 1 до 24** рабочих дней.
- По умолчанию: **24 дня**.
- Механизм: `workDaysCount` управляет, сколько сетов показывается из массива `MONTHLY_SETS`.
- **🆕 v1.2 (ручной ввод):** значение дней — кликабельный `input type="number"`: можно вписать число с клавиатуры. Кнопки «−»/«+» остаются по бокам → [[COMPONENTS#9-steppertsx-счётчик-с-ручным-вводом-v12]].
- **🆕 Фикс (v1.1):** При уменьшении количества дней **дни за пределами лимита автоматически деактивируются** в `cartState` (предотвращает баг «24 из 11»).
- **🆕 Фикс (v1.3):** При **увеличении** количества дней **новые дни автоматически активируются** — день `N+1` подгружается в выбранные, итоговая сумма и количество порций мгновенно растут (`handleWorkDaysSet`). Ранее (v1.1) новые дни оставались неактивными.
- «Выбрать все N дней» активирует строго `workDaysCount` дней, «Сбросить все» деактивирует только видимые дни (синхронизированы с ручным вводом).

```typescript
// App.tsx
const visibleSets = MONTHLY_SETS.slice(0, workDaysCount)

// handleWorkDaysSet(count):
//   уменьшение (clamped < prev) → active: false для дней numId > clamped
//   увеличение (clamped > prev) → active: true  для дней numId ∈ (prev, clamped]
```

## 5. Логика employeeCount как множителя

- `employeeCount` (по умолчанию `1`) — количество сотрудников компании.
- Этот параметр **умножает** стоимость:
  - `totalItems = totalPortionsFromActive × employeeCount`
  - `totalMonthlyPrice = totalItems × SET_PRICE`
- Минимальное значение: `1`
- Начальное значение: `1` (сбрасывается при `handleNewOrder()`)

- По умолчанию: `'Вода'`.

## 7. Включение/выключение дней (Toggle)

- Каждый день можно **включить** или **исключить** из подписки.
- UI: кастомный toggle-переключатель (CSS-only, без JS).
- По умолчанию: **все дни включены** (`active: true`).
- Массовые операции:
  - **«Выбрать все N дней»** — `handleSelectAll()` (активирует строго `workDaysCount` дней)
  - **«Сбросить все»** — `handleDeselectAll()` (деактивирует только в пределах `workDaysCount`)

## 8. Исключение ингредиентов (v1.3)

- В модалке сета ([[COMPONENTS#5-setdetailmodaltsx]]) второстепенные компоненты — **Салат, Лепёшка, Напиток** — кликабельны.
- При клике ингредиент **исключается**: серый чип с зачёркиванием переносится в блок **«Без этих ингредиентов»**; повторный клик возвращает его обратно.
- 🛡️ **Защита от абуза:** основное блюдо (main dish) **заблокировано** от исключения (`disabled` + `Lock` + подсказка `mainDishLocked`). Убрать главное блюдо НЕЛЬЗЯ.
- Исключения хранятся в `cartState[id].excludedIngredients: string[]` ([[STATE_MANAGEMENT#2-2-cartstate—детальная-структура]]) и **сохраняются в итоговом объекте заказа** (`lines[].excludedIngredients`) → [[CHECKOUT_FLOW#5-2-обработка-заказа]].
- В [[COMPONENTS#6-carttsx—экран-корзиныоформления]] для таких дней отображается строка «без: Салат, Лепёшка».
- **Цена не меняется** при исключении ингредиентов (фиксированный сет 55 000 сум).

## 9. Количество порций (Portions)

- Для каждого активного дня можно указать количество порций на одного сотрудника.
- Минимум: `1`
- По умолчанию: `1`
- UI: счётчик `--` / `значение` / `++`.
- Кнопка `--` отключается при `portions <= 1`.

## 10. Форма оформления заказа (Cart)

### 10.1. Текущее состояние

⚠️ **Важно:** На данный момент форма заказа **минимальна**.  
В `Cart.tsx` отображаются:

- Список выбранных сетов с детализацией (день, напиток, порции, цена)
- Выбор **способа оплаты** (см. п. 9.2)
- Итоговая сумма

**Поля, которые НЕ реализованы, но подразумеваются бизнес-логикой:**

| Поле                     | Описание                              | Статус       |
| ------------------------ | ------------------------------------- | ------------ |
| Имя / ФИО контактного лица | Кто оформляет заказ                  | ❌ Не реализовано |
| Телефон                  | Контактный номер телефона             | ❌ Не реализовано |
| Адрес доставки           | Куда доставлять обеды                 | ❌ Не реализовано |
| Окно времени доставки    | Желаемое время доставки               | ❌ Не реализовано |
| ИНН / Название компании  | Для юрлиц (при оплате перечислением)  | ❌ Не реализовано |
| Комментарий              | Дополнительные пожелания              | ❌ Не реализовано |

### 10.2. Способы оплаты (PaymentMethod)

| Метод          | Значение      | Описание (RU)              | Эмодзи |
| -------------- | ------------- | -------------------------- | ------ |
| Перечислением  | `'corporate'` | Для юридических лиц        | 🏢     |
| Перевод на карту | `'card'`    | P2P перевод                | 💳     |
| Наличными      | `'cash'`      | Наличными курьеру          | 💵     |

🆆 **Локализация:** подписи кнопок оплаты переведены на узбекский (Ko'chirma orqali, Kartaga o'tkazma, Naqd pul).

По умолчанию: `'corporate'`.

### 10.3. Процесс оформления

1. Пользователь нажимает «Оформить предзаказ» / «Buyurtma berish» в Catalog
2. Открывается экран Cart с детализацией
3. Выбор способа оплаты
4. Нажатие «Оплатить N сум» / «N so'm to'lash»
5. `handlePlaceOrder(method)` → `console.log` + локализованный `alert` → `setScreen('success')`
6. Экран Success с анимацией и номером заказа
7. Кнопка «Сделать новый заказ» / «Yangi buyurtma» → полный сброс
