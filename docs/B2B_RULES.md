## 1. Бизнес-модель

Lunchistan — сервис корпоративной подписки на комплексные обеды.  
Компании подписываются на **ежемесячную доставку обедов** для своих сотрудников.

---

## 2. Меню — 22 рабочих дня

- **22 обеда** на месяц (Пн–Пт × 4–5 недель).
- Каждый день — **уникальный сет** (основное блюдо + салат + лепёшка + напиток).
- Данные хранятся в `src/data/mockMenu.ts` как массив `MONTHLY_SETS`.
- Пример основного блюда: «Гушт сай с лепёшкой», «Курица с грибами и рисом» и т.д.

### 2.1. Формат описания сета

```
Обед День X (ДеньНедели) — Основное блюдо + Салат + Лепёшка + Напиток
```

Пример:  
`Обед День 1 (Пн) — Гушт сай с лепёшкой + Салат + Лепёшка + Напиток`

---

## 3. Ценообразование

### 3.1. Базовая цена

| Параметр           | Значение                         |
| ------------------ | -------------------------------- |
| **Цена одного сета** | **55 000 сум** (фиксировано)   |
| Константа          | `export const SET_PRICE = 55000` |

### 3.2. Формула стоимости

```
totalPortionsFromActive = Σ(portions каждого активного дня)
totalItems = totalPortionsFromActive × employeeCount
totalMonthlyPrice = totalPortionsFromActive × employeeCount × SET_PRICE
```

Где:
- `employeeCount` — количество сотрудников (множитель)
- `portions` — количество порций на одного сотрудника для конкретного дня (по умолчанию 1)
- `active` — включён ли день в подписку

### 3.3. Пример расчёта

```
Сотрудников: 10
Активных дней: 20 (по 1 порции на день)
Итого: 20 × 10 × 55 000 = 11 000 000 сум
```

## 4. Гибкое количество рабочих дней

- Пользователь может выбрать **от 1 до 22** рабочих дней.
- По умолчанию: **22 дня**.
- Механизм: `workDaysCount` управляет, сколько сетов показывается из массива `MONTHLY_SETS`.
- При изменении количества дней **не сбрасываются** настройки напитков/порций для уже видимых сетов.

```typescript
// App.tsx
const visibleSets = MONTHLY_SETS.slice(0, workDaysCount)
```

---

## 5. Логика employeeCount как множителя

- `employeeCount` (по умолчанию `1`) — количество сотрудников компании.
- Этот параметр **умножает** стоимость:
  - `totalItems = totalPortionsFromActive × employeeCount`
  - `totalMonthlyPrice = totalItems × SET_PRICE`
- Минимальное значение: `1`
- Начальное значение: `1` (сбрасывается при `handleNewOrder()`)

## 6. Выбор напитка (Beverage)

### 6.1. Доступные варианты

| Вариант                      | Тип       | Эмодзи |
| ---------------------------- | --------- | ------ |
| **Вода**                     | `'Вода'`  | 💧     |
| **Компот в ассортименте**    | `'Компот в ассортименте'` | 🧃 |

### 6.2. UI: стильные кнопки (pill-group)

Реализованы как группа стилизованных кнопок **pill-group**:

```tsx
<div className="pill-group">
  <button className="pill pill--active">💧 Вода</button>
  <button className="pill">🧃 Компот</button>
</div>
```

- `pill--active` — оранжевый фон + белый текст.
- Выбор применяется **индивидуально к каждому дню**.
- По умолчанию: `'Вода'`.

---

## 7. Включение/выключение дней (Toggle)

- Каждый день можно **включить** или **исключить** из подписки.
- UI: кастомный toggle-переключатель (CSS-only, без JS).
- По умолчанию: **все дни включены** (`active: true`).
- Массовые операции:
  - **«Выбрать все N дней»** — `handleSelectAll()`
  - **«Сбросить все»** — `handleDeselectAll()`

---

## 8. Количество порций (Portions)

- Для каждого активного дня можно указать количество порций на одного сотрудника.
- Минимум: `1`
- По умолчанию: `1`
- UI: счётчик `--` / `значение` / `++`.
- Кнопка `--` отключается при `portions <= 1`.

## 9. Форма оформления заказа (Cart)

### 9.1. Текущее состояние

⚠️ **Важно:** На данный момент форма заказа **минимальна**.  
В `Cart.tsx` отображаются:

- Список выбранных сетов с детализацией (день, напиток, порции, цена)
- Выбор **способа оплаты** (см. п. 9.2)
- Итоговая сумма

**Поля, которые НЕ реализованы, но подразумеваются бизнес-логикой:**

| Поле                     | Описание                              | Статус       |
| ------------------------ | ------------------------------------- | ------------ |
| Имя / ФИО контактного лица | Кто оформляет заказ                  | ❌ Не реализовано |
| Телефон                  | Контактный номер телефона             | ❌ Не реализовано |
| Адрес доставки           | Куда доставлять обеды                 | ❌ Не реализовано |
| Окно времени доставки    | Желаемое время доставки               | ❌ Не реализовано |
| ИНН / Название компании  | Для юрлиц (при оплате перечислением)  | ❌ Не реализовано |
| Комментарий              | Дополнительные пожелания              | ❌ Не реализовано |

### 9.2. Способы оплаты (PaymentMethod)

| Метод          | Значение      | Описание                 | Эмодзи |
| -------------- | ------------- | ------------------------ | ------ |
| Перечислением  | `'corporate'` | Для юридических лиц      | 🏢     |
| Перевод на карту | `'card'`    | P2P перевод              | 💳     |
| Наличными      | `'cash'`      | Наличными курьеру        | 💵     |

По умолчанию: `'corporate'`.

### 9.3. Процесс оформления

1. Пользователь нажимает «Оформить предзаказ» в Catalog
2. Открывается экран Cart с детализацией
3. Выбор способа оплаты
4. Нажатие «Оплатить N сум»
5. `handlePlaceOrder(method)` → `console.log` + `alert` → `setScreen('success')`
6. Экран Success с анимацией и номером заказа
7. Кнопка «Сделать новый заказ» → полный сброс
